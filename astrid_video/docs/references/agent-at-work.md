# Agent at Work

A refined dark terminal sits beside the tangible creative result on a warm editorial canvas. Use actual requests and concise summaries of recorded actions/results. This is an authored replay visualization, not a live agent monitor or a recreation of hidden reasoning. The default and included preview are explicitly illustrative generated fixtures. Do not label attempted or waiting operations completed, invent timings or imply false correspondence between media and a result.

## Authoring contract

`request` is a readable user direction; `events` is an ordered list of `{id, at, duration, text, detail?, status?, reveals?}` in clip-local seconds. Text streams at `typeRate`; a short completion detail appears only after the event ends. `status` is the terminal outcome (`done`, `failed`, `waiting`); active events display a working marker. Each output ID is revealed exactly once by a completed event. A failed or waiting event cannot reveal successful results. The most recent rows occupy a bounded terminal panel; use short lines and avoid raw logs. `panelRatio` controls the split (0.27–0.48), day/night changes the editorial surface; the terminal remains dark. Landscape is the primary intended presentation.

The output is one of two ordinary authored shapes, not a new timeline format:

- `output.kind: cards`: supply a variable collection of up to eight text, image or video cards, each with a stable id, label, asset or text; video has `sourceStart` and `sourceEnd`. A completion event reveals a card at its reserved grid position. Examples: reference collection, generated variants, actual plan, feedback/result. Video clocks begin at reveal and freeze at the last declared source frame.
- `output.kind: timeline`: supply an existing [timeline visualizer](timeline-visualizers.md) settings object under `timeline`, including the actual clips and rendered player outputs. Declare mediaBindings only at the outer activity params. Reveal the same clip IDs through events, then at `assembleAt` advance the existing assembly engine's clock. The same pool cards travel into their tracks; when the edit is ready, `expandAt` and `expandSeconds` enlarge the same timeline view to full canvas and recede the terminal. Output is a real supplied rendered cut, not generated by the visualization itself. Use an existing timeline element independently for other playback sequences.

Optional `mink` is the same [performer cue vocabulary](mink-performance.md). It can run, pause, wave, exit or appear behind the terminal. Keep it small and occasional. Use `depth: behind` for peek/perch staging with actual panel geometry. The activity remains legible without the mascot. The performer uses immutable declared assets; project media uses logical managed slots, never arbitrary paths. The general host integration still depends on #1870.

## Example

[Timeline handoff](example-agent-at-work.yaml) uses the existing generated six-component demo edit: prepare sources, graphics and moving clips, assemble, reveal the actual final cut. [Flexible cards](example-agent-cards.yaml) is an independent reference-gathering replay including a waiting state. Both are editable parameters, not new implementations. Preserve real output IDs, verified source clocks and exact timeline identity in a film; no platform actions are executed by this effect. A native Astrid placement/render still needs host admission and media projection. The standalone Python raster previews use the actual TypeScript frame model but are not native export evidence.
