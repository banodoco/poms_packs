# Agent reply reveal

A reusable authoring recipe for a staged conversation reply. The persistent question, identity and optional model badge frame a changing message body: animated thinking states, one to three capability cards, then a resolved reply. This is an illustration of agent activity, not a display of hidden reasoning or a live execution trace.

Use `replyRevealRecipe` in `extensions/reply-reveal.ts`; it expands to canonical Living Composition poses, so existing renderers, bindings, pixel transitions, and deterministic frame evaluation apply. Supply ordinary static image assets for each visible state, including the agent identity and brand icon. The model badge is optional and arrives at its own cue; the identity and badge keep their positions and payloads once visible. Thinking dot variants loop at 0.32 seconds; the body transforms into capability cards and back into the answer. The first card retains the body identity, other cards enter/exit using the existing composition transition. The caller supplies the duration, fps and phase arrivals and binds each image asset through `mediaBindings`. Quantization and phase-order checks fail closed. For a different speaker or task replace the supplied art and cues, not the renderer. This recipe is an author-time helper, not a new native effect, UI widget or chat backend.

Example input: `{question:"question",identity:"agent",model:"model",thinking:["dots1","dots2","dots3"],details:["tools","workflows","guidance"],answer:"answer",headerAt:0.5,modelAt:1.5,detailsAt:3,answerAt:5,duration:7,fps:24}`. Use `node preview/reply-author.cjs` with this JSON on stdin to obtain the composition. Attach the ordinary asset bindings before rendering. Real model identifiers and execution claims must be verified before publication; use explicit illustration labels for simulated activity.
