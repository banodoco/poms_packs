# Continuous Sequence (v0.15 candidate)

**An optional island of continuity, not a replacement timeline.** An agent composes native editable effects or existing authored output videos, then connects them with deliberate viewport moves. A persistent visual panel has an ID, independent rectangle and source clock. The camera and optional actor are separate authored settings. A finished film, hard cut or ordinary overlay need not use this effect at all.

The implemented element `continuous-sequence` uses `shared/sequence/model.ts` and `view.tsx`. The same pure TypeScript model drives the offline review renderer. It reuses the existing Mink Performer model and immutable sprite assets. No new Astrid core contract, renderer protocol, or mandatory scene DSL.

## Input contract

The wrapper `{duration,params}` is a review convention; only `params` is the element payload. The outer clip duration is in seconds. All authored times are clip-local seconds. The compiler quantizes camera arrivals to frames. World coordinates use viewport units: one unit in x is the canvas width, one unit in y is its height at zoom 1. `world.width` and `height` are bounds for actor coordinate normalization, not a rendered oversized bitmap. Limit to 24 panels, 64 camera destinations and 64 actor cues. Use the [example](example-continuous-sequence.json).

- `panels`: `{id,kind,rect,...}`. Kinds `title` (title/eyebrow/subtitle), `image` or `video` (logical asset slot, bounded sourceStart/sourceEnd in seconds for video). A rectangle is `{x,y,width,height}`; optional `poses` are timed destinations with smooth interpolation. `visibleAt`/`hideAt` gate visibility; optional `z` orders panels; `frame` adds a border. `playAt` sets the source clock start. Before it the first frame holds, after the declared end the last frame holds. The camera never restarts a media clock. Use `mediaBindings` and native host-resolved inputs, not author paths, URLs or copied project media. Separate audio from the muted panel videos.
- `camera`: a list of `{at,target|center,zoom?,mode?,duration?,lead?}`. `target` frames a panel at the arrival; explicit `center` is a world point. First entry at zero. `move` interpolates from previous destination, `follow` blends towards the world actor during the move then lands exactly at the authored frame; `lead` is a world-relative camera offset, `cut` changes immediately, `hold` retains framing. Between moves the camera is stationary. No camera or actor integration state; seeking is deterministic. Prefer modest zoom and short purposeful moves. A follow target does not itself imply automatic collision avoidance.
- `actor` is optional. `space: world` follows camera geometry, `space: screen` is a viewport-relative overlay. `start` and `size` define the first foot anchor and sprite-cell height relative to the viewport. `anchors` can be world points or `{panel,u,v}` (relative point on a panel, resolved at the cue's arrival). Moving-panel attachment after arrival is not yet implemented; author a subsequent destination. `cues` reuse Mink Performer, plus `depart` (reverse settle frames) and `present` (held existing raised-paw pose). Use explicit durations. `behind` identifies a panel painted above the actor; otherwise the actor is frontmost. No physical navigation or live cross-clip actor state. Sprite playback, path and camera remain independent.
- `soundCues(compiled)` yields clip-relative frame/sound suggestions for run contacts (initial provisional indices 0 and 5 in the original 11-frame cycle). These are editable suggestions, not an audio render or a calibrated foot-contact classifier. Convert to ordinary timeline sound clips with the correct sequence offset. Inspect/audition the actual gait before a final mix.

## Scope and handoffs

A panel can be a retained rendered asset from an existing effect. The creator's native timeline, media references and original source parameters remain authoritative; the wrapper does not import another renderer's implementation. A later richer adapter can expose live frame-state/anchors of an existing composition, but this candidate does not automatically transfer object identity across different arbitrary effects, continuously attach actors to animated panels, expose a new editor track type or run multiple nested renderer backends. Preserve source and result provenance and use ordinary cuts between islands. This intentionally demonstrates the narrow camera/actor contract first.

## Reproduction and verification

From the distribution root: `tsc --target es2020 --module commonjs --strict --rootDir astrid_video --outDir preview astrid_video/shared/sequence/model.ts`; `node preview/test-sequence.cjs`; `python preview/render_sequence.py preview/sequence-demo.json review/sequence-demo.mp4 preview/timeline-media 960 540 24`. The last example has no media inputs or performer. The preview path accepts local PNG/MP4 fixture files named by slot; it is not host resolution. Native Remotion compilation, admission, arbitrary managed media, preview/export parity and placement are outstanding under Plan 99/#1870. The offline rasterizer uses substitute fonts and image sampling. Review the visual sequence and audio, not just compiler tests.
