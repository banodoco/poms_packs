# Extend the choreography vocabulary

Keep a single Living Composition engine. The code is split into `shared/composition/{types,compile,engine}.ts`, `extensions/{layouts,behaviours,accents,recipes}.ts`, and a Remotion effect component. The existing `shared/organism.ts`, `shared/deck/motion.ts` and `shared/style.ts` are reused. Legacy shuffle and arm display remain intact for compatibility; new recipes can express their core behaviours but the legacy renderers are not migrated yet.

- A **layout** is a pure `LayoutFn(LayoutContext) -> Rect[]` registered in `LAYOUTS`. It receives ordered identities, actual aspect ratios, the safe area and canvas aspect. It returns normalized rectangles in the same order. No timing, media decoding or particles. `diagonal` is a worked additional layout.
- A **behaviour** is a `Behaviour.draw(BehaviourContext)` registered in `BEHAVIOURS`. It adds to the shared Tissue grid using current box, root, frame, identity seed, effort, movement, growth, flow, spread and strength. `root: true` requests the common root. Use full-footprint colonies or porous streams; borrow behaviour, not anatomy. Do not draw over content except with the explicit contact layer. No per-frame random state.
- An **accent** is an `AccentFn(AccentContext)` registered in `ACCENTS`. It sees resolved target geometry, optional second target, progress, absolute frame and seed; it paints tissue. It cannot alter media timing or primary layout. `pixel-connect` is an example using shared swimmers. More complex foreground accents need an explicit typed render contract rather than bypassing the engine.
- A **recipe** produces a canonical composition, not another renderer. `shuffleRecipe` and `presentationRecipe` illustrate authoring helpers. Prefer recipes and documented parameter defaults. A recipe may be ordinary YAML or a pure function.

To add a contribution, read the effect-design skill, add the smallest module or registry entry, declare every new file in pack.yaml, update the corresponding element schema enum/parameters, document input limits and provide a small authored example. Add tests for determinism, bounds, zero/maximum controls, endpoints and a render review. Verify old examples still work. Registries are explicit and static because Astrid project pack import closure must be declared; no runtime plug-in loading or external dependencies. Cross-pack extensions require a supported Astrid dependency mechanism and are not implemented here.

Do not mistake these primitives for full physics. The compiler stages exchanges and retains IDs, but complex collision avoidance and physically conserved particles across resizing are future work. The creator judges actual motion. The core renderer should remain ignorant of new layout geometry and accent-specific algorithms.
